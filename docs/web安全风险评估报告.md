## 5 详细漏洞实验过程与分析

### 5.1 高危漏洞一：登录暴力破解漏洞

#### 5.1.1 漏洞原理

登录接口未对登录次数、请求频率、访问IP做任何限制，无验证码、无令牌校验，攻击者可批量枚举密码，暴力破解后台账号。

#### 5.1.2 实验复现过程

1. 访问 DVWA 系统登录页面，正常输入账号密码。
2. 开启 Burp Suite 抓包，拦截登录 POST 请求数据包。
3. 将数据包发送至 Intruder 爆破模块，锁定密码参数位置。
4. 加载常用弱口令字典，开始批量枚举测试。
5. 观察回显长度与状态差异，成功匹配正确密码。
6. 使用爆破成功的账号密码登录系统，验证漏洞有效。

#### 5.1.3 实验现象

服务器未拦截高频请求，可无限尝试密码，最终成功爆破有效账号密码。

#### 5.1.4 漏洞危害

攻击者可批量获取后台账号，越权登录后台，窃取业务数据、篡改网站内容。

#### 5.1.5 修复方案

1. 增加登录失败次数锁定机制。
2. 接入图形验证码、行为验证码防止机器爆破。
3. 限制单IP单位时间请求次数。
4. 强制密码复杂度策略，禁止弱口令。

---

### 5.2 高危漏洞二：系统命令注入漏洞

#### 5.2.1 漏洞原理

后端将用户输入内容**直接拼接系统命令执行**，未过滤管道符、分隔符等特殊字符，导致用户可控输入可拼接额外系统指令。

#### 5.2.2 实验复现过程

1. 进入 Command Injection 命令执行模块。
2. 正常输入 IP 可正常执行 ping 功能。
3. 构造恶意组合 Payload：`127.0.0.1 | whoami`。
4. 提交参数，页面同时执行 ping 命令与系统查询命令。
5. 页面成功输出服务器当前用户信息，漏洞复现成功。

#### 5.2.3 实验现象

用户可控参数被直接带入系统内核执行，可随意查询系统信息。

#### 5.2.4 漏洞危害

攻击者可执行查看文件、读写文件、下载木马、权限提升等恶意操作，完全控制服务器。

#### 5.2.5 修复方案

1. 禁止直接拼接用户输入至系统命令。
2. 采用白名单机制，仅允许数字、IP、小数点。
3. 使用专用函数封装网络检测功能，禁用原生系统调用。

---

### 5.3 高危漏洞三：本地文件包含漏洞（LFI）

#### 5.3.1 漏洞原理

页面通过 GET 参数动态加载文件，后端未过滤路径穿越字符，用户可自定义读取服务器任意本地文件路径，造成任意文件读取漏洞。

#### 5.3.2 实验复现过程

1. 进入 File Inclusion 文件包含页面。
2. 观察 URL 参数 page 可控，页面动态加载 PHP 文件。
3. 构造绝对路径 Payload：`?page=/etc/passwd`。
4. 访问链接，页面成功读取服务器系统账号配置文件。
5. 证明服务器存在严重本地文件包含与路径遍历漏洞。

#### 5.3.3 实验现象

可直接读取系统敏感配置、账号文件、日志文件、源码文件。

#### 5.3.4 漏洞危害

泄露服务器架构、系统账号、网站源码、数据库配置等核心敏感信息。

#### 5.3.5 修复方案

1. 文件加载采用**文件名白名单机制**。
2. 过滤 `../` `./` `/` 等路径穿越字符。
3. 关闭 PHP 危险包含参数，限制文件读取权限。

---

### 5.4 高危漏洞四：无限制文件上传漏洞

#### 5.4.1 漏洞原理

文件上传功能仅前端简单判断，后端**无文件后缀校验、无文件头校验、无MIME校验**，可直接上传可执行脚本文件，造成服务器后门植入。

#### 5.4.2 实验复现过程

1. 新建一句话木马文件 `shell.php`，写入PHP执行代码。
2. 进入文件上传模块，直接选择 PHP 木马文件上传。
3. 系统无任何拦截，提示上传成功并返回完整路径。
4. 复制上传地址，使用蚁剑新建连接，填写木马地址与连接密码。
5. 测试连接成功，进入服务器文件管理界面，可浏览、修改、删除服务器文件。

#### 5.4.3 实验现象

恶意脚本成功上传并可解析执行，完全控制网站目录。

#### 5.4.4 漏洞危害

攻击者上传 Webshell 后门，永久控制 Web 服务器，窃取数据、挂黑页、批量渗透内网。

#### 5.4.5 修复方案

1. 后端严格校验文件后缀，仅允许图片格式。
2. 校验文件头部真实文件特征，防止后缀伪造。
3. 上传目录设置禁止 PHP 脚本执行权限。
4. 上传文件随机重命名，杜绝路径可控。

---

### 5.5 高危漏洞五：显错型SQL注入漏洞

#### 5.5.1 漏洞原理

后端 SQL 语句直接拼接用户输入参数，未使用预编译语句，未过滤特殊字符，攻击者可通过单引号闭合原有SQL结构，重构任意数据库查询语句。

#### 5.5.2 实验复现过程

1. 进入 SQL Injection 注入页面，输入 `1'`。
2. 页面爆出数据库语法错误，证明参数存在注入点。
3. 使用 `order by` 语句探测字段数，确认共2个字段。
4. 构造 union 联合查询语句，读取数据库名称、系统版本。
5. 构造查表 Payload，成功查询网站所有用户账号与加密密码。

#### 5.5.3 实验现象

数据库数据直接外漏，所有用户敏感信息可任意查询。

#### 5.5.4 漏洞危害

脱库获取全站账号密码、业务数据、管理员权限数据，造成严重数据泄露。

#### 5.5.5 修复方案

1. 全站使用 **预编译参数化SQL查询**。
2. 关闭生产环境数据库错误回显。
3. 过滤单引号、#、and、union 等特殊关键字。

---

### 5.6 高危漏洞六：布尔型SQL盲注漏洞

#### 5.6.1 漏洞原理

页面无报错、无数据回显，仅根据SQL执行结果返回两种页面状态（存在/不存在）。攻击者可通过真假逻辑语句，逐位猜解数据库所有内容。

#### 5.6.2 实验复现过程

1. 进入 SQL Blind 布尔盲注页面。
2. 输入真值语句：`1' and 1=1#`，页面提示用户存在。
3. 输入假值语句：`1' and 1=2#`，页面提示用户不存在。
4. 页面出现明显差异，证明存在布尔盲注。
5. 可通过 substr 逐字符截取数据库名称、表名、字段内容。

#### 5.6.3 实验现象

虽然不直接返回数据，但可通过页面差异暴力猜解全部数据库信息。

#### 5.6.4 漏洞危害

攻击者可通过脚本自动化爆破整库数据，危害等同于普通注入。

#### 5.6.5 修复方案

1. 统一错误页面，消除真假页面差异。
2. 严格过滤SQL特殊字符与逻辑关键字。
3. 使用预编译查询杜绝SQL语句拼接。

---

### 5.7 中危漏洞七：CSRF跨站请求伪造

#### 5.7.1 漏洞原理

关键业务接口（改密、改资料）仅依赖 Cookie 鉴权，无 CSRF Token、无来源校验，攻击者可伪造请求诱导用户执行非自愿操作。

#### 5.7.2 实验复现过程

1. 进入修改密码功能，抓包发现请求无任何校验令牌。
2. 构造恶意修改密码 URL 链接。
3. 用户处于登录状态时访问恶意链接。
4. 系统直接执行改密操作，用户密码被强制篡改。

#### 5.7.3 实验现象

无需用户确认、无需验证，直接完成敏感操作。

#### 5.7.4 漏洞危害

可篡改用户密码、绑定恶意信息、劫持账号、发起批量钓鱼攻击。

#### 5.7.5 修复方案

1. 关键请求加入随机 CSRF Token 校验。
2. 校验请求 Referer、Origin 来源。
3. 敏感操作增加短信/弹窗二次确认。

---

### 5.8 中危漏洞八：反射型XSS跨站脚本

#### 5.8.1 漏洞原理

用户输入内容直接反射输出至页面，无 HTML 转义、无标签过滤，浏览器会直接解析执行 JavaScript 代码。

#### 5.8.2 实验复现过程

1. 进入反射型 XSS 测试页面。
2. 输入标准 XSS 弹窗 Payload`。
3. 点击提交，页面成功弹出脚本弹窗。
4. 证明恶意代码被浏览器成功解析执行。

#### 5.8.3 实验现象

可控输入点可任意执行 JS 代码，属于典型反射型 XSS。

#### 5.8.4 漏洞危害

攻击者构造钓鱼链接，窃取用户 Cookie、劫持会话、伪造页面内容。

#### 5.8.5 修复方案

1. 前端输出数据进行 HTML 实体编码转义。
2. 后端过滤 script、iframe、onerror 等危险标签事件。
3. 配置 CSP 内容安全策略。

---

### 5.9 中危漏洞九：存储型XSS跨站脚本

#### 5.9.1 漏洞原理

留言板功能将用户输入**持久化存入数据库**，前台展示数据时未转义，导致恶意脚本永久存储，所有访问页面用户均会触发攻击。

#### 5.9.2 实验复现过程

1. 进入留言板存储型 XSS 页面。
2. 昵称随意填写，留言内容插入 JS 攻击代码。
3. 提交留言，页面自动触发弹窗。
4. 刷新页面、重启访问依然触发漏洞，证明代码已存入数据库。

#### 5.9.3 实验现象

漏洞永久生效，持久性强、影响所有访问用户。

#### 5.9.4 漏洞危害

批量盗取所有访客 Cookie、挂马、钓鱼、长期劫持页面。

#### 5.9.5 修复方案

1. 入库前过滤危险脚本标签。
2. 出库展示前强制 HTML 转义。
3. 禁止用户提交可执行前端脚本。

---

### 5.10 低危漏洞十：弱口令安全风险

#### 5.10.1 漏洞原理

系统测试账号使用简单通用弱口令，不符合密码复杂度策略，极易被字典爆破与暴力枚举。

#### 5.10.2 实验过程

1. 查看现有账号密码，密码简单、长度短、无复杂度。
2. 极易被暴力破解、社工猜测。

#### 5.10.3 漏洞危害

账号容易被劫持，引发后续越权、数据泄露、后台沦陷等次生风险。

#### 5.10.4 修复方案

1. 强制密码大小写、数字、特殊符号组合。
2. 禁止常见弱口令字典。
3. 定期强制密码轮换。

## 6 漏洞风险等级汇总

### 6.1 高危漏洞（6个）

暴力破解、命令注入、文件包含、文件上传、SQL显注入、SQL盲注

> 
> 可直接拿下服务器、脱库、获取核心权限，危害极大

### 6.2 中危漏洞（3个）

CSRF伪造请求、反射型XSS、存储型XSS

> 
> 可劫持用户、钓鱼、会话窃取，可配合漏洞扩大危害

### 6.3 低危漏洞（1个）

弱口令风险

> 
> 合规性不达标，存在辅助攻击风险

## 7 整体漏洞成因总结

所有 Web 漏洞根源均可归纳为以下四点：

1. **用户输入完全可信，无过滤、无校验、无转义**
2. **后端代码直接拼接用户可控内容执行**
3. **关键操作缺少 Token、验证码、二次校验**
4. **前端输出数据未做编码转义，直接渲染**

## 8 通用安全加固规范

1. 所有用户输入严格白名单校验。
2. 数据库查询统一使用预编译参数化语句。
3. 系统命令、文件读取、文件上传等高风险功能严格权限控制。
4. 前端输出全部做 HTML 转义处理。
5. 所有敏感操作增加令牌校验与二次确认。
6. 服务器遵循最小权限原则部署配置。
