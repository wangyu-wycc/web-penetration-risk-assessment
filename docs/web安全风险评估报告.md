# Web 应用安全风险评估报告（DVWA 完整复现版）

## 1 项目概述

本次测试基于 **DVWA 漏洞测试靶场** 开展全流程黑盒渗透测试，模拟真实安全工程师渗透流程，覆盖登录认证、命令执行、权限伪造、文件操作、SQL 查询、前端输入输出等核心业务场景。

严格按照 **等保 2.0、CVSS3.1 风险评级标准**，完成漏洞探测、手工复现、危害分析、风险定级、落地整改建议，完整复现 **10 类高频 Web 漏洞**，真实还原 Web 安全常见攻击链路与防御短板。

## 2 测试环境

- **测试靶场**：DVWA（Low 安全级别，全程手工复现）
- **测试环境**：本地虚拟机内网环境
- **测试工具**：Burp Suite、蚁剑、浏览器原生调试、手工 Payload 构造
- **测试方式**：纯人工黑盒测试，无自动化扫描工具

## 3 测试范围与整体流程

本次测试覆盖 DVWA 全部核心漏洞模块，完整流程如下：

1. **功能探测**：遍历系统所有用户可控输入点、上传点、请求参数、链接跳转功能
2. **漏洞探测**：手工构造特殊字符、闭合语句、拼接 Payload 验证漏洞
3. **漏洞复现**：全程完整复现攻击链路，留存截图证据
4. **风险定级**：根据危害范围、权限影响、数据泄露程度划分高、中、低危
5. **整改编写**：针对每类漏洞给出企业可落地的开发级修复方案
6. **安全总结**：归纳 Web 应用通用安全缺陷与开发规范

## 4 漏洞汇总与详细分析

### 4.1 高危漏洞（共 6 项）

#### 4.1.1 账号暴力破解漏洞

**风险描述**：系统登录接口无验证码、无登录次数限制、无请求频率拦截，攻击者可通过 Burp Suite 批量枚举密码，暴力破解后台账号。

**复现过程**：抓取登录 POST 数据包，加载密码字典进行爆破，成功枚举有效账号密码并登录后台。

**整改建议**：增加登录失败锁定策略、接入图形验证码、限制接口请求频率、禁止弱口令。

#### 4.1.2 系统命令注入漏洞

**风险描述**：Ping 功能直接拼接用户输入至系统命令执行，未做任何过滤，攻击者可通过管道符拼接任意系统指令。

**复现过程**：构造 payload `127.0.0.1 | whoami`，成功执行系统命令，读取服务器账户信息。

**整改建议**：禁止直接拼接用户输入调用系统 Shell；采用函数封装 Ping 逻辑；输入白名单校验。

#### 4.1.3 本地文件包含漏洞（LFI）

**风险描述**：页面 `page` 参数可控，未过滤路径穿越符，攻击者可遍历服务器任意本地敏感文件。

**复现过程**：构造绝对路径 payload 读取 `/etc/passwd`，成功获取服务器系统账号清单，造成信息泄露。

**整改建议**：文件加载采用白名单机制；过滤 `../`、`/` 等遍历字符；关闭危险包含配置。

#### 4.1.4 无限制文件上传漏洞

**风险描述**：上传模块未校验文件后缀、文件类型，允许直接上传 PHP 脚本木马。

**复现过程**：上传一句话木马 `shell.php`，通过蚁剑成功连接服务器，实现文件读写、权限控制。

**整改建议**：校验文件头真实类型、仅允许图片格式；上传目录禁止脚本执行；随机重命名文件。

#### 4.1.5 显错 SQL 注入漏洞

**风险描述**：后端 SQL 语句直接拼接用户输入，未使用预编译，可通过单引号闭合查询语句。

**复现过程**：通过 `order by` 判断字段数，union 联合查询成功读取数据库名、版本、用户账号密码密文。

**整改建议**：全站采用参数化预编译查询；关闭详细 SQL 错误回显；特殊字符过滤转义。

#### 4.1.6 布尔型 SQL 盲注漏洞

**风险描述**：页面无数据回显、无报错信息，仅通过页面真假状态判断 SQL 执行结果，存在布尔盲注风险。

**复现过程**：构造 `1' and 1=1#`、`1' and 1=2#` 形成页面返回差异，可逐位爆破库、表、字段数据。

**整改建议**：统一页面错误提示，消除真假返回差异；严格过滤 SQL 特殊字符。

### 4.2 中危漏洞（共 3 项）

#### 4.2.1 跨站请求伪造 CSRF 漏洞

**风险描述**：密码修改接口无 CSRF Token 校验，仅依赖 Cookie 鉴权，可伪造用户请求篡改密码。

**复现过程**：构造恶意 URL，用户登录状态下访问即可无需验证直接修改账户密码。

**整改建议**：关键操作加入随机 CSRF 令牌；校验 Referer 请求源；敏感操作增加二次确认。

#### 4.2.2 反射型 XSS 跨站脚本

**风险描述**：前端输入内容直接反射输出页面，无转义过滤，恶意 JS 代码可直接执行。

**复现过程**<script>alert</script>`，成功弹窗执行脚本，可窃取用户 Cookie。

**整改建议**：前端输出 HTML 实体编码；过滤危险标签与事件；配置 CSP 安全策略。

#### 4.2.3 存储型 XSS 跨站脚本

**风险描述**：留言板功能将恶意脚本持久化存入数据库，所有访问用户均会触发攻击，危害高于反射型 XSS。

**复现过程**：提交 JS 脚本留言，页面加载自动执行恶意代码，实现持久化攻击。

**整改建议**：入库前过滤、出库前转义；禁止存储危险 HTML、JS 标签。

---

### 4.3 低危漏洞（共 1 项）

#### 4.3.1 弱口令安全风险

**风险描述**：测试账号使用简单弱口令，容易被暴力枚举、爆破破解，不符合密码复杂度规范。

**整改建议**：强制大小写 + 数字 + 特殊符号复杂度；定期密码轮换；弱口令拦截机制。

## 5 风险等级说明

- **高危**：可直接获取服务器权限、数据库数据、批量泄露敏感信息、完全控制业务核心
- **中危**：可劫持用户会话、伪造请求、执行前端恶意代码，可配合其他漏洞提权利用
- **低危**：不直接危害核心权限，但存在信息暴露、合规性不达标问题

## 6 整体安全整改总结

根据本次 10 项漏洞复现结果，Web 应用主要安全缺陷集中在：

1. **用户输入完全可控，无过滤、无转义、无校验**
2. **后端代码直接拼接语句，未采用安全编码规范**
3. **关键接口无 Token、无验证、无防护机制**
4. **文件、命令、数据库等高危操作信任用户输入**

**通用修复规范：**

- 所有输入点严格白名单校验
- 数据库统一预编译参数化查询
- 输出前端数据强制 HTML 转义
- 上传、修改密码等关键操作增加安全校验
- 最小权限原则配置服务器与目录权限
